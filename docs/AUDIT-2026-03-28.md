## Executive Summary

Polyforge has an impressive feature set for a solo-founder project — 16 Docker services, whale tracking, copy trading, AI news-to-trade, gasless transactions, 3 SDKs, an MCP server, and comprehensive admin tooling. The architecture is sound and security fundamentals are strong.

However, **the codebase is not deployment-ready**. There are 5 critical blockers that must be resolved before shipping, plus ~30 high/medium issues that should be addressed in the first weeks post-launch.

**Issue count by severity:**

| Severity | Count | Summary |
|----------|-------|---------|
| CRITICAL | 5 | Blocks deployment or causes data loss/security breach |
| HIGH | 12 | Will cause bugs, crashes, or integration failures in production |
| MEDIUM | 15 | Technical debt that compounds over time |
| LOW | 8 | Polish and best practices |

## CRITICAL — Must Fix Before Deploy

### C1. SQL Injection in Markets Service
**File:** `services/api-service/src/markets/markets.service.ts:106-126`
**Issue:** `$queryRawUnsafe()` with unparameterized ORDER BY clause.
**Risk:** An attacker can inject arbitrary SQL through the sort parameter.
**Fix:** Use parameterized query or whitelist allowed column names.

### C2. 69 Duplicate JS/TSX Files in Frontend Apps
**Files:** 47 in `apps/user-app/src/`, 22 in `apps/admin-app/src/`
**Issue:** Incomplete TypeScript migration left both `.js` and `.tsx` versions of the same components. Vite may resolve the wrong file depending on config, causing stale code to run.
**Fix:** Delete all `.js` duplicates after confirming `.tsx` versions are complete.

### C3. SDK ↔ MCP ↔ Backend API Path Mismatch (BLOCKING for integrations)
| Component | Path Pattern | Strategy Create Endpoint |
|-----------|-------------|--------------------------|
| MCP Server | `/api/v1/*` | `/api/v1/strategies/from-description` |
| TS SDK | `/*` (no prefix) | `/strategies/generate` |
| Python SDK | `/api/*` | `/api/strategies/generate` |
| Rust SDK | `/api/*` | `/api/strategies/from-description` |

**Impact:** Every SDK and the MCP server will fail to communicate with the backend. This is 4 components all disagreeing on URL structure.
**Fix:** Decide on one canonical path pattern, update all 4 repos.

### C4. Missing Cascading Deletes in Prisma Schema
**Issue:** Only 1 cascade defined across 50+ foreign key relationships. Deleting a user or strategy leaves orphaned orders, copy configs, webhook registrations, etc.
**Risk:** Data integrity failures, storage bloat, potential privacy violations (user data not fully deleted).
**Fix:** Audit all relations, add `onDelete: Cascade` or implement soft-delete with cleanup jobs.

### C5. Admin App Missing Error Boundary
**File:** `apps/admin-app/src/app.tsx:16-30`
**Issue:** `RouterProvider` not wrapped with ErrorBoundary (user-app does this correctly).
**Risk:** Any uncaught error in admin panel crashes the entire app with a white screen.
**Fix:** Wrap with ErrorBoundary matching user-app pattern.

## HIGH — Fix in Sprint 1 Post-Deploy

### H1. TS SDK Hardcoded Production URL
**File:** `polyforge-sdk-ts/src/client.ts:25`
**Issue:** Default URL is `https://api.polyforge.io/v1` — a domain that doesn't exist yet. Other SDKs default to `localhost:3002`.
**Fix:** Align all SDKs to same default, or require explicit URL.

### H2. TSConfig Hierarchy Broken
**Issue:** All 13 services and 3 apps do NOT extend root `tsconfig.json`. Each has independent compiler settings.
**Impact:** `noImplicitAny: false` in services means type bugs slip through. Mixed `module` settings (CommonJS vs ESNext) across packages.
**Fix:** All packages should extend root tsconfig with targeted overrides only.

### H3. React Version Split
| Package | React Version |
|---------|--------------|
| apps/user-app | 18.3.x |
| apps/admin-app | 19.x |
| apps/landing | 19.x |
| packages/ui | 19.x |

**Impact:** Shared UI components built for React 19 may break in user-app. Hook behavior differences between versions.
**Fix:** Upgrade user-app to React 19.

### H4. Fire-and-Forget Promise in Auth Guard
**Issue:** API key usage tracking is fire-and-forget — can silently fail without logging.
**Fix:** Add `.catch()` with error logging.

### H5. Unvalidated Admin Cache Flush
**Issue:** Admin endpoint accepts arbitrary pattern parameter for Redis cache flush without validation.
**Risk:** Could flush entire cache with `*` pattern.
**Fix:** Whitelist allowed patterns or require exact key.

### H6. JWT Cache Race Condition
**Issue:** In-memory JWT cache without thread-safety. Thundering herd eviction on size limit.
**Fix:** Use LRU cache with proper eviction or move to Redis.

### H7. Rust SDK Missing URL Encoding
**File:** `polyforge-sdk-rust/src/client.rs:126-145`
**Issue:** Query string built with `format!()` — no URL encoding. Special characters in values will break requests.
**Fix:** Use `url::form_urlencoded` or `reqwest`'s built-in query params.

### H8. Admin API Never-Resolving Promise on 401
**File:** `apps/admin-app/src/lib/api.ts:43-44`
**Issue:** After refresh token failure, returns `new Promise<T>(() => {})` — a promise that never resolves. Causes hanging requests.
**Fix:** Reject the promise and redirect cleanly.

### H9. Zero Test Coverage in All SDKs + MCP
**Issue:** No test files exist in any of the 4 external repos (polyforge-mcp, sdk-ts, sdk-python, sdk-rust).
**Fix:** At minimum, add integration tests against mock server for each SDK.

### H10. Error Messages Exposed to Users
**File:** `apps/user-app/src/components/error-boundary.tsx:50`
**Issue:** Raw `error.message` rendered in UI. Could expose stack traces or internal info.
**Fix:** Show generic message, log full error.

### H11. N+1 Query Patterns in Market Listing
**Issue:** Market listing and portfolio endpoints load relationships separately. Currently masked by Redis caching, but cache misses cause performance spikes.
**Fix:** Use Prisma `include` or join queries.

### H12. Missing React Keys in Admin App Lists
**Files:** `admin-app/src/pages/invites/invites.tsx:130` (missing entirely), plus 10+ files using index as key.
**Impact:** List reordering causes state bugs.
**Fix:** Add stable unique keys to all `.map()` renders.

## MEDIUM — Fix Within 4 Weeks

### M1. TypeScript Version Split (5.7 vs 5.9)
Frontend apps on 5.7, all services on 5.9. Different compiler behavior.

### M2. ESLint sourceType Conflict
Root config assumes `commonjs` but user-app uses ESNext modules.

### M3. Invalid Workspace Entries
`services/gateway/` and `apps/gateway/` are nginx configs, not Node packages, but included in pnpm-workspace.yaml.

### M4. Hardcoded Localhost URLs in Vite Configs
`apps/user-app/vite.config.ts` and `apps/admin-app/vite.config.ts` hardcode `localhost:3001` and `localhost:3002`.

### M5. Python SDK Sync/Async Code Duplication
500+ lines duplicated between sync and async client implementations.

### M6. Incomplete Event Sync in Market Data Service
3 TODO comments indicate Event model syncing disabled pending schema updates.

### M7. Hardcoded Gas Estimates in Signer Service
Static gas cost predictions instead of real-time oracle.

### M8. Console Statements in Production Code
`console.error` in error-boundary, `console.log` in api-docs page.

### M9. Terraform .tfvars Not in .gitignore
Production secrets in variable files could accidentally be committed.

### M10. Missing Prisma Generated Clients in CI
`.prisma/client` and `.prisma/admin-client` need generation step in build pipeline.

### M11. WASM Build Artifacts Not Verified
`packages/polyforge-crypto` and `packages/polyforge-engine` have `build:wasm` scripts but no verified output.

### M12. Python SDK Uncertain Response Format
Multiple fallback checks (`isinstance(data, list) else data.get("items", ...)`) suggest the API response format isn't stable.

### M13. Direct DOM Manipulation in Tooltip Tour
`document.querySelector` and `classList` manipulation instead of React refs.

### M14. Redis Single-Node (No Failover)
Production Redis has no replication group configured.

### M15. Encryption Key Rotation Not Implemented
`MASTER_ENCRYPTION_KEY` rotation outlined in docs but implementation is TBD.

## Positive Findings (What's Working Well)

The audit isn't all problems. These are genuinely strong:

- **Network segmentation**: 4 isolated Docker networks properly separating concerns
- **Signer service hardening**: Read-only filesystem, no exposed ports, dropped capabilities
- **Secrets management**: AWS Secrets Manager, not environment variables
- **Database encryption**: At-rest and in-transit
- **CORS whitelisting**: Explicit origin validation, not wildcards
- **Rate limiting**: Login lockout after 10 failures (15 min cooldown)
- **RBAC**: 3 roles (SUPER_ADMIN, ADMIN, VIEWER) with proper enforcement
- **Audit logging**: All auth events tracked
- **Multi-AZ RDS**: Automatic failover configured
- **Health checks**: All 12 verified services have health endpoints
- **Webhook security**: HMAC-SHA256 signature validation
- **CI/CD gating**: E2E tests + production environment approval gate
- **Dockerfiles**: Multi-stage builds, non-root user, frozen lockfile
